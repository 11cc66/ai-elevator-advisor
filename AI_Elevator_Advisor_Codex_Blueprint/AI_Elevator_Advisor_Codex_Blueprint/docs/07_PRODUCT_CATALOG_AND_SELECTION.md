# 07 — 产品数据库与选型引擎

## 1. 产品数据字段

每个产品至少应维护：
- 品牌；
- 制造商；
- 型号；
- 产品配置；
- 载重；
- 额定速度；
- 适用楼层 / 层站；
- 适用提升高度；
- 井道净宽要求；
- 井道净深要求；
- 底坑要求；
- 顶部空间要求；
- 开门尺寸；
- 机房 / 无机房配置；
- 驱动配置；
- 布置图和技术文件；
- 技术资料来源；
- 资料更新时间；
- 技术资料有效状态；
- 企业审核状态；
- 价格地区、币种、价格类型、价格范围；
- 价格来源、更新时间和有效期。

参数应支持“未知 / 不适用 / 有值”，不能用 0 代替缺失值。

## 2. 产品数据质量

- 型号唯一性规则需考虑制造商、型号、配置组合。
- 重复记录不得自动合并。
- 参数冲突时暂停正式推荐并建立核实事项。
- 技术资料和价格资料分别版本化。
- 技术审核通过不代表价格有效；价格有效也不代表技术适用。
- 未审核产品不得进入正式推荐。

## 3. 选型分层

### 第一层：数据准入
只读取当前版本、来源明确、企业审核通过的产品技术数据。价格另行判断有效性。

### 第二层：工程硬约束
根据经专业确认的工程条件过滤：
- 载重；
- 速度；
- 层站 / 提升高度；
- 井道尺寸；
- 底坑；
- 顶部空间；
- 机房配置；
- 开门及其他必要配置。

缺失关键条件时，停止正式型号推荐，输出缺失项。

### 第三层：偏好排序
在通过硬约束的产品中，结合：
- 客户预算；
- 使用体验偏好；
- 运行速度；
- 载重余量；
- 配置；
- 可维护性资料；
- 有效价格。

排序权重必须可解释、可配置，不可让模型凭主观印象给分。

## 4. 三档方案

- ECONOMY：经济实用，优先控制成本；
- BALANCED：均衡舒适，兼顾价格和体验；
- PREMIUM：高配置，更重视配置和体验。

规则：
- 三档都必须先满足工程硬约束。
- 合格产品不足三款，不强行凑齐。
- 同一产品可否出现在多个档位需由排序规则决定，并向客户解释。
- 预算默认是参考；客户明确说“绝对不能超过”才作为硬预算约束。
- 价格缺失或过期时可保留技术合格产品，但价格标为待询价，不可推测。
- 设备价格与项目总造价分开。

## 5. 筛选结果必须可解释

每款产品保存：
- 通过 / 排除 / 待核实；
- 每条通过或排除原因；
- 使用的产品参数版本；
- 使用的工程数据快照；
- 规则版本；
- 价格引用；
- 筛选时间。

## 6. 模拟数据

`examples/demo_catalog.json` 只用于开发和演示，字段中应明确 `data_classification: "DEMO_MOCK"`。禁止将其当作真实厂家资料或真实价格。
