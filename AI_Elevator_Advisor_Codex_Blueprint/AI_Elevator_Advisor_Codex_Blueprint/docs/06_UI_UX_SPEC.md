# 06 — 页面结构与交互要求

## 1. 客户端底部导航

四个主入口：
1. 首页
2. 我的项目
3. 售后服务（V1.0 可先做基础信息 / 占位状态）
4. 我的

## 2. 首页

- 第一视觉中心为 AI 智能顾问。
- 提供“旧楼加装”“旧梯改造”“新楼安装”入口；V1.0 实际完整流程先只开放旧楼加装，其余显示规划中或咨询入口。
- 对话区支持文本消息。
- 支持上传资料。
- 有“我的项目”快捷入口。
- AI 通过对话逐步收集需求，不把专业术语表单直接抛给客户。

## 3. 项目详情

建议分区：
- 项目概况；
- 建筑信息；
- 安装单元；
- 资料文件；
- 待确认 / 待核实事项；
- 勘察进度；
- 选型方案；
- 报价；
- 项目动态。

多栋楼项目必须清楚展示当前建筑和安装单元，避免资料串楼。

## 4. 资料识别界面

每个识别字段显示：
- 字段和值；
- 来源文件；
- 页码 / 图片定位（可用时）；
- 识别状态；
- 是否可由客户确认；
- 待核实原因。

客户只能确认普通事实；专业工程字段显示“待专业人员核实”，不提供一键升级为专业确认的操作。

## 5. 企业后台

建议侧边栏：
- 工作台；
- 客户；
- 项目；
- 勘察任务；
- 产品库；
- 选型审核；
- 报价管理；
- 审计日志；
- 用户与权限。

## 6. 产品库界面

- 产品列表、搜索和筛选；
- 产品技术资料版本；
- 价格版本；
- 数据来源；
- 有效期；
- 审核状态；
- 重复 / 冲突提示；
- 导入预览和错误报告；
- 审核、停用和历史版本。

## 7. 方案展示

- 经济、均衡、高配置三档；
- 显示真实可用参数、差异和限制；
- 缺失数据显示待确认；
- 价格显示来源、地区、更新时间、有效期；
- 设备价格与项目总造价分开；
- 客户可比较任意两款；
- 只向客户展示已发布的方案版本。

## 8. 通用交互

每个页面必须考虑：
- 加载状态；
- 空状态；
- 错误状态；
- 无权限状态；
- 保存成功 / 失败；
- 版本变化提示；
- 移动端响应式布局；
- 可访问性和清晰的中文文案。
